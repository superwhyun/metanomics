# Metanomic

게임 A에서 받은 공통 코인을 게임 B에서 사용하고, 판매 수입을 다시 보상으로 사용하는 중앙 운영형 프로토타입입니다. 실제 ERC-20·정산 계약, HTTP API, 영속 작업 처리기를 포함합니다. 게임은 운영자가 신청·등록하며, 저장소의 예제 게임(`src/game.ts`)은 통합 테스트와 연동 참고용입니다.

## 다른 게임에 연동하기

- [게임 개발자 연동 가이드](docs/GAME_INTEGRATION.md): 서버 설정, 게임 지갑 로그인, 주소 기반 보상·결제 요청 예제, 아이템 지급과 재시작 복구, 완료 기준.
- [다른 에이전트에 전달할 작업 지시서](docs/AGENT_GAME_INTEGRATION_TASK.md): 대상 게임 경로와 게임 ID를 채워 전달하는 구현 작업 템플릿.
- [지갑과 권한 구조](docs/WALLETS.md): 관리자·중계 지갑, 관리자 로그인 지갑, 운영자·이용자 지갑의 권한과 관계, 신뢰 모델, 운영 체크리스트.
- [OpenAPI JSON](docs/openapi.json): 실제 API 요청·응답 스키마. 실행 중인 서버에서는 <http://localhost:3300/docs>로 확인합니다.

게임 등록은 사용자 카탈로그 공개까지 담당합니다. 보상·결제에는 게임 서버 연동이 필요합니다. 현재 범용 로그인 리다이렉트·호스팅 결제창·배포용 SDK는 제공하지 않으며, 외부 게임의 지갑 로그인·결제 승인 화면은 각 게임에서 구현합니다. 일반 이용자는 Metanomic 가입이나 게임별 연결 코드 없이 게임에 지갑으로 로그인해 보상을 받습니다.

## 서버 실행

Node.js 22.13 이상과 npm이 필요합니다. Node 22의 SQLite 실험 기능 안내는 정상입니다.

```sh
npm ci
npm run dev
# 같은 실행: npm start
```

기존 `var/saigon.env`의 `CONFIG_PATH`로 외부 Ronin 테스트넷 설정과 DB를 읽습니다. 로컬 블록체인 노드 실행, 계약 재배포, 초기화는 하지 않습니다. 설정이 없거나 로컬 체인 설정이면 이유를 출력하고 종료합니다. 다른 환경은 `ENV_FILE=/path/to/external.env npm start`로 선택할 수 있으며, 직접 지정한 환경변수가 파일보다 우선합니다.

- 화면: <http://localhost:3300>
- OpenAPI UI: <http://localhost:3300/docs>
- OpenAPI JSON: <http://localhost:3300/openapi.json>
- 블록체인 연결: 외부 Ronin Saigon RPC

시작 시 기존 계약과 중계 권한을 검증합니다. 성공하면 API가 실행되며, 종료는 터미널에서 Ctrl+C입니다. 포트를 다른 서버가 사용하거나 하위 프로세스가 종료되면 원인을 알리고 함께 종료합니다. API만 실행하려면 `node --env-file=var/saigon.env --import tsx src/main.ts`를 사용합니다.

모든 역할이 지갑으로 로그인합니다. 운영 서버는 아이디·비밀번호 로그인(`POST /v1/sessions`)을 거부하며, 관리자는 관리자 계정에 등록된 로그인 지갑으로 들어옵니다. 자동화·점검에 비밀번호 로그인이 필요하면 `PASSWORD_LOGIN=1`로 서버를 실행합니다. 초기 계정 비밀번호는 `var/bootstrap-accounts.json`에 있습니다. 새로 설치하면 포털 첫 화면이 **관리자 로그인 지갑 연결**로 시작합니다. 배포 때 출력된 초기 설정 코드(`var/admin-setup-code`)를 입력하고 관리자로 쓸 지갑으로 서명하면 그 지갑이 관리자 로그인 지갑이 되고, 연결이 끝날 때까지 일반 로그인은 표시하지 않습니다. 코드는 한 번만 쓸 수 있으며, 관리자 지갑을 잃으면 서버에서 `node --env-file=var/saigon.env --import tsx scripts/admin-setup-code.ts`로 새 코드를 발급해 같은 방법으로 연결합니다. 초기 설정이 만든 샘플 게임(`game-a`, `game-b`)과 샘플 계정(`operator`, `player`)은 `node --env-file=var/saigon.env --import tsx scripts/retire-samples.ts`로 운영 환경에서 제외합니다. 샘플 게임은 계약에서 운영 중지되고 샘플 계정은 로그인할 수 없으며, 기존 거래 기록은 회계를 위해 유지합니다.

## 지갑으로 로그인

연결을 처음부터 다시 하려면 **지갑 연결 초기화**를 누릅니다. 이 브라우저의 Metanomic 로그인과 연결 상태를 비우고 현재 서버 세션을 종료합니다. 지갑이 사이트 권한 해제 API를 지원하면 연결 권한도 해제합니다. Ronin에서 자동 해제가 지원되지 않으면 **Settings → Connected dApps → localhost → Disconnect**에서 직접 해제한 뒤 **지갑으로 로그인**을 다시 누릅니다. 지갑 삭제·초기화나 복구 구문 재입력은 필요하지 않습니다. 기존 계정·구매·보상 기록과 계정에 등록한 지갑 주소는 유지합니다.

첫 화면에서 **지갑으로 로그인 → Ronin Wallet 또는 MetaMask 선택 → 로그인 메시지 서명** 순서로 진행합니다. 일반 EVM 개인키 지갑을 지원하며, 로그인 서명은 가스비나 토큰 사용 승인을 요구하지 않습니다. [SIWE (ERC-4361)](https://eips.ethereum.org/EIPS/eip-4361) 메시지를 서버에서 검증하고 기존과 같은 로그인 세션을 발급합니다.

처음 사용하는 지갑은 일반 이용자로 가입됩니다. 로그인할 때마다 지갑에 계정 선택을 다시 요청하고, 지갑이 이 사이트에 여러 계정을 연결해 두었으면 포털에서 사용할 계정을 고릅니다. 지갑이 계정 재선택(EIP-2255)을 지원하지 않으면 이전에 연결한 계정이 그대로 쓰이므로, 다른 계정으로 바꾸려면 지갑의 Connected dApps에서 이 사이트 연결을 해제하거나 다른 계정도 연결해 두세요. 기존 이용자의 수령 지갑이나 미리 등록된 관리자·운영자 승인 지갑은 기존 계정으로 로그인됩니다. **기존 계정에 새로운 지갑을 붙이려면** 그 계정에 이미 등록된 지갑으로 로그인한 뒤, **로그인 지갑 등록**을 누르고 지갑 소유 확인에 서명하세요. 기존 게임·구매·보상 기록과 역할은 그대로 유지됩니다. 이미 다른 계정으로 사용한 지갑은 자동으로 합치거나 이전하지 않습니다.

로그인 지갑 등록은 계약의 관리자·운영자 승인 주소를 바꾸지 않습니다. 게임 보상은 해당 게임에서 로그인한 지갑으로 받습니다. 결제·예치·인출은 거래 내용에 따로 서명합니다. 새 지갑 계정에는 아이디·비밀번호 로그인 자격증명을 만들지 않습니다. 스마트 계약 지갑 검증은 이번 범위에 포함하지 않습니다.

로그인 요청은 5분 이내 한 번만 사용할 수 있고 세션은 메시지 발급 후 최대 8시간입니다. 사이트·체인·주소·용도에 묶인 메시지를 검증합니다. 지갑 로그인 후 연결한 확장 프로그램에서 계정을 바꾸거나 연결을 해제하면 포털은 로그아웃합니다. 페이지를 새로 열었을 때는 저장된 세션을 사용하며, 거래 서명 전 지갑 계정·네트워크를 다시 확인합니다.

## 게임 운영자 신청

1. 지갑으로 로그인해 일반 이용자로 가입합니다.
2. **게임 운영자 신청** 탭에서 운영사·개발자 이름, 연락처, 소개를 입력하고 지갑으로 소유 확인 메시지에 서명합니다. 서명한 지갑이 운영자 승인 지갑이 됩니다. 다른 계정에 연결된 지갑이나 네트워크 운영용 지갑은 사용할 수 없습니다.
3. 관리자가 **등록 심사 → 게임 운영자 신청 검토**에서 승인하면 그 계정이 운영자로 전환됩니다. 반려하면 사유를 남기며 이용자는 보완해 다시 신청할 수 있습니다.
4. 승인 지갑은 게임을 등록할 때 계약에 운영자 주소로 기록되며 이후 바꿀 수 없습니다. 예치·인출 승인은 이 지갑으로 서명합니다.

관련 API는 `POST /v1/operator-applications/challenges`, `POST /v1/operator-applications`, `GET /v1/operator-applications`, 관리자 승인·반려 경로입니다.

## 운영자의 게임 등록과 이용자 공개

1. 운영자 계정으로 로그인하고 **게임 등록 신청**을 작성합니다. 이름, 장르, 소개, 실행할 웹 주소를 입력하면 게임 ID(`game-` + 무작위 8자리)는 서버가 발급합니다.
2. 관리자 `admin` 계정으로 로그인해 **게임 등록 신청 검토**에서 승인합니다. 반려할 때는 사유를 남기며, 운영자는 신청 현황의 **다시 신청**으로 내용을 보완해 같은 게임 ID로 다시 신청합니다.
3. 계약 등록 거래가 블록에 포함되면(보통 몇 초) 이용자의 **참여 게임** 목록에 이름·소개·장르·실행 링크가 자동으로 나타납니다. 신청 중이거나 등록이 실패한 게임은 공개하지 않습니다.
4. 운영자의 **내 게임 운영**에 승인된 게임이 나타납니다. **게임 서버 연결** 메뉴에서 API 주소·게임 ID를 복사하고 게임 API 키를 발급받아 서버의 지갑 로그인·보상·결제를 연동합니다. 신규 게임의 초기 보상 예산은 0이며 관리자가 배분하거나 운영자가 예치합니다.

게임 자체는 입력한 운영자의 웹 주소에서 실행됩니다. 관리자가 **게임 관리**에서 게임을 끄면 즉시 이용자 목록에서 빠지고 새 결제·보상이 막힙니다. 블록체인 거래는 일어나지 않습니다. 서버와 관계없이 계약이 막게 하려면 **체인에 중지 기록**을 누릅니다. 관리자 지갑 거래 1건이며 확정되면 포털도 꺼집니다. **체인에 재개 기록**은 계약만 다시 열고, 포털은 확정 후 **켜기**로 켭니다. 꺼진 게임은 **삭제**로 포털에서 지울 수 있으며, 끝나지 않은 결제가 있으면 삭제할 수 없습니다. 결제·보상 기록과 블록체인 장부의 남은 예산은 그대로 남습니다. 관리자 예산 배분의 게임 목록도 켜진 게임만 보여줍니다.

관련 API는 `POST /v1/game-registrations`, `GET /v1/game-registrations`, 관리자 승인·반려 경로, `GET /v1/operator/games`, 공개 카탈로그 `GET /v1/games`입니다. OpenAPI 화면에서 요청 형식을 확인할 수 있습니다.

## 이용자 흐름

1. 원하는 CGC 연동 게임을 열고 사용자 지갑으로 로그인합니다. Metanomic의 사전 가입이나 게임별 계정 연결 코드는 필요 없습니다.
2. 게임이 플레이 결과를 판정해 로그인한 지갑 주소로 CGC를 지급합니다. 게임 서버는 인증된 게임 세션의 주소를 사용합니다.
3. 다른 게임에서도 같은 지갑으로 로그인하고 CGC 결제를 지갑으로 승인할 수 있습니다. 게임 서버가 승인 서명을 중계하므로 포털 로그인은 필수가 아닙니다.
4. 잔액·보상·결제 내역을 모아 보고 싶으면 Metanomic 포털에 같은 지갑으로 로그인합니다. 포털 첫 로그인 전의 주소 기반 내역도 조회됩니다.

포털의 **내 공통 코인**은 최신 블록에 반영된 CGC 잔액을 보여주고, 아래에 **최종 확정 잔액**과 **확정 전 변동**을 구분합니다. 확정 전 변동은 최신 잔액에서 최종 확정 잔액을 뺀 순변동으로 입금·출금에 따라 양수 또는 음수가 됩니다. 아직 블록에 포함되지 않은 보상 요청은 합산하지 않으며, 확정 전에는 체인 재구성으로 잔액이 바뀔 수 있습니다. 최신 잔액 조회에 실패하면 확정 잔액을 대신 표시하고, 둘 다 확인하지 못하면 0 대신 조회 실패를 안내합니다. 보상·결제의 업무 완료 판정은 계속 최종 확정 기준입니다.

예제 게임의 지갑 로그인과 실제 계약의 보상 → 결제 → 추가 보상 흐름은 `tests/wallet-game-login.test.ts`에서 검증합니다. 지갑 로그인은 게임 자체의 세션을 발급하며 별도 포털 이용자를 만들지 않습니다. 게임별 계정 연결 API와 `playerId` 요청은 기존 연동의 호환 경로로 유지합니다. 직접 토큰을 이전한 내역은 구매·보상 내역에 포함하지 않습니다.

운영자 화면은 예치·인출, 자격증명 발급·폐기, 미완료 결제를 제공합니다.

관리자 화면의 **예산·발행**에서 게임 보상 예산을 배분합니다. 검색할 수 있는 목록에서 게임을 고르고, `+10`·`+100` 같은 단위 버튼이나 슬라이더로 금액을 정한 뒤 **한 번만**, **매주**(요일), **매월**(1~28일) 중 하나를 고릅니다. 반복 배분은 정한 날 서버 시간 0시에 자동으로 배분하며, 서버가 꺼져 있었거나 게임이 꺼진 회차는 건너뛰고 몰아서 보내지 않습니다. 등록한 반복 배분은 같은 화면의 **반복 배분** 표에서 일시 중지·재개·삭제합니다.

같은 화면에서 CGC를 발행 상한 안에서 추가 발행할 수 있습니다. 네트워크 보유분에 발행하면 예산 배분 재원이 늘고, 운영자 지갑에 발행하면 운영자가 자기 게임 예산에 직접 예치할 수 있습니다. 발행은 되돌릴 수 없으며 관리자 지갑이 서명합니다. **현황**에서 중계 지갑과 관리자 지갑의 RON 잔액을 확인하고, 부족하면 Ronin Saigon faucet으로 충전합니다. 중계 지갑은 1분마다 잔액을 확인해 기준치(`RELAYER_MIN_RON`, 기본 0.5) 미만이면 관리자 지갑에서 `RELAYER_TOPUP_RON`(기본 2)만큼 자동으로 충전하며, 관리자 지갑에는 `ADMIN_MIN_RON`(기본 0.5)을 남깁니다. `RELAYER_AUTO_FUND=0`이면 자동 충전을 끕니다. 같은 카드의 **관리자 지갑에서 충전**으로 원하는 양을 직접 보낼 수도 있습니다. 평소에는 관리자 지갑만 faucet으로 채우면 됩니다. 운영자·관리자 서명은 계약에 등록된 각 역할의 지갑으로 승인합니다. 중계 키는 화면에 노출하지 않습니다.

### 확장 프로그램 지갑 연결

확장 프로그램에서 지갑 생성·잠금 해제를 마친 뒤 Metanomic을 새로고침하고 **지갑 앱 연결 → Ronin Wallet 등 사용할 지갑 선택** 순서로 진행합니다. 확장 프로그램에서 계정 연결과 현재 환경의 네트워크 추가·전환을 승인합니다. 관리자·운영자의 연결 주소는 **승인 지갑** 영역에 표시됩니다. 일반 이용자는 각 게임의 지갑 로그인 메시지에 서명하면 됩니다. 포털에서 보상 지갑을 별도로 연결하지 않습니다.

지갑 인식은 EIP-6963, Ronin의 `window.ronin.provider`, 기존 `window.ethereum`을 지원합니다. 여러 지갑이 설치되어 있으면 이용자가 선택하며, 소유 확인과 결제 서명도 같은 제공자로 보냅니다. 지갑의 계정이나 네트워크가 바뀌면 재연결을 요구합니다. 지갑이 목록에 없으면 같은 Chrome 프로필에 설치했는지와 현재 사이트에 대한 확장 프로그램 접근 권한을 확인하고 새로고침하세요.

Ronin에서 Sign을 눌렀어도 지갑이 서명값 대신 `WALLET_IS_LOCKED`를 반환하면 로그인은 완료되지 않습니다. 잔액 화면이 열려 있는데도 발생하면 지갑을 한 번 잠근 뒤 지갑 비밀번호로 다시 열어 내부 상태를 갱신하고 재시도하세요. 이 오류 코드만으로 사용자가 지갑 잠금 해제를 하지 않았다고 단정할 수는 없습니다. 앱 로그인 비밀번호와 지갑 잠금 해제 비밀번호는 별개입니다.

문제가 반복될 때 개발자는 <http://localhost:3300/wallet-check.html>에서 로그인과 분리된 최소 메시지 서명을 확인할 수 있습니다. 이 페이지는 연결 승인과 `personal_sign`만 요청하고 반환된 서명을 검증합니다. 체인 전환·계정 조회·서버 로그인·거래 제출을 하지 않으며 원문 지갑 오류를 표시합니다.

### 로그인 지갑 별명

로그인 후 **지갑·계정 → 로그인 지갑**에서 본인 등록 지갑의 사이트 별명을 저장·수정·삭제합니다. 앞뒤 공백은 제거하고 연속 공백·탭·줄바꿈은 한 칸으로 정리하며, 정리 후 최대 40자(UTF-16 기준)입니다. 빈 값 저장도 별명 삭제로 처리하고 지갑 등록은 유지합니다.

다음 로그인에서 확장 프로그램이 여러 연결 계정을 반환하면 **별명 · 짧은 주소**로 표시합니다. 같은 별명도 주소로 구분하며 **전체 주소 확인**을 펼칠 수 있습니다. 새 주소나 알려진 별명이 없는 주소는 **이름 미등록**입니다. 별명은 지갑 앱에서 읽는 이름이 아니라 Metanomic의 표시 정보이며, 소유 확인·권한·서명은 계속 주소를 기준으로 합니다.

별명은 서버에 저장하고, 로그인 후 받은 본인 지갑 별명만 해당 사이트의 브라우저 저장소에 캐시합니다. 로그아웃·지갑 연결 초기화 후에도 캐시는 남습니다. 다른 브라우저의 변경은 다시 로그인해 목록을 받을 때 반영됩니다. 저장소가 차단되거나 캐시가 손상되면 이름 미등록으로 선택할 수 있고 로그인 후 서버의 별명이 복원됩니다. 로그인 전 임의 주소의 별명을 조회하는 공개 API는 제공하지 않습니다.

## 검증과 산출물

지갑 별명 브라우저 회귀 테스트는 `npx playwright install chromium`을 한 번 실행한 후 `npm run test:wallet-aliases:web`으로 실행합니다. 격리된 메모리 DB·임의 포트의 API·모의 지갑 서명을 사용하며 기존 서버·DB·실제 Ronin 확장 프로그램에 연결하지 않습니다.

```sh
npm run check
npm run build:web
npm run openapi
npm audit
```

`check`는 TypeScript 검사, Solidity 컴파일, 실제 Anvil 계약·HTTP·게임 DB 통합 테스트를 실행합니다. 테스트는 임시 디렉터리와 임의 포트를 사용하며 개발 DB를 바꾸지 않습니다.

- 계약: `contracts/`
- 공통 API·서명·복구: `src/`
- 브라우저 화면: `web/`, `public/`
- 독립 예제 게임: `src/game.ts`, `src/game-main.ts`
- 생성된 API 규격: `docs/openapi.json` — 런타임의 요청·응답 스키마에서 생성
- 운영 규칙: [설계·복구 명세](docs/DESIGN.md)
- 검증 결과와 배포 현황: [검증 기록](docs/VERIFICATION.md)

## 확정 방식 (`FINALITY`)

기본값 `FINALITY=finalized`는 RPC의 `finalized` 블록을 기다린다(Saigon에서 약 20~30분). `FINALITY=depth`와 `CONFIRMATIONS=N`(1~1000 정수)을 지정하면 N번 확인된 블록을 확정으로 간주한다. 거래가 포함된 블록 자체가 1회 확인이므로 1은 블록에 포함되는 즉시, 5는 포함 후 4블록이 더 쌓였을 때다. 시퀀서 체인 기준의 소프트 확정이라 L1 최종성을 보장하지 않으며, 그보다 깊은 재구성이 일어나면 이미 `FINALIZED`로 기록된 업무 결과는 자동으로 되돌리지 않는다. 설정은 배포 전체에 적용되므로 보상·결제뿐 아니라 인출·발행·예산 이동에도 같은 기준이 쓰인다. 저장된 배포 설정은 바꾸지 않으며, 서버 시작 때 환경 변수가 있으면 그 값으로 덮어쓴다. 로컬 체인(`local`) 배포는 영향받지 않는다. `scripts/status.ts`는 같은 설정으로 확정 블록과 지연을 보고한다.

### 게임별 정산 속도

운영자는 **내 게임 운영**의 **정산 속도**에서 자기 게임의 확인 블록 수(1~1000)를 정할 수 있다(`PUT /v1/games/{gameId}/settlement`, `{ "confirmations": 5 }`). `null`이나 빈 값은 서버 기본값을 따른다. 보상(`reward`)과 결제(`pay`·`claimDelivery`·`fulfill`·`refund`)와 해당 결제의 상태 조회에만 적용되고, 예산 배분·예치·인출, 발행, 게임 등록, 복구 승인은 항상 서버 기본값을 쓴다. 설정 변경은 감사 기록에 남으며, 이미 처리 중인 작업에도 다음 처리 주기부터 새 값이 적용된다. 1을 고르면 체인 재구성 시 이미 반영한 보상·결제가 사라질 수 있고 그 위험은 해당 게임이 진다.

## Saigon 테스트넷

현재 Saigon의 chain ID는 `202601`입니다. 계약과 키는 로컬 환경과 분리합니다. 현재 설정은 RPC의 `finalized`를 기다리므로 거래 포함보다 완료가 상당히 늦을 수 있습니다. 실제 관측된 약 20분의 지연을 반영해 외부 배포의 승인·지급 시작 기한은 60분입니다. 로컬 기본값은 15분입니다.

[공식 네트워크 정보](https://docs.roninchain.com/developers/network)는 현재 Saigon을 OP Stack으로 안내합니다. 메인넷의 L1 최종 확정 안내 시간은 약 12분이며, 이를 테스트넷의 완료 시간 보장으로 사용하지 않습니다. 이번 검증의 실제 지연과 결과는 별도 검증 기록에 남깁니다.

새 테스트 환경을 만드는 절차:

```sh
npx tsx scripts/bootstrap-saigon.ts
# var/saigon.env의 ADMIN 주소로 공식 faucet에서 테스트 RON 수령
node --env-file=var/saigon.env --import tsx scripts/fund-relayer.ts
node --env-file=var/saigon.env --import tsx scripts/deploy.ts   # 초기 설정 코드 출력
node --env-file=var/saigon.env --import tsx scripts/retire-samples.ts
npm run dev
# 포털 첫 화면에서 초기 설정 코드로 관리자 로그인 지갑 연결
```

검증용 배포에서 예제 게임까지 확인하려면 `retire-samples` 전에 `scripts/smoke.ts`를 실행합니다.

`bootstrap-saigon.ts`는 이미 있는 키 파일을 덮어쓰지 않습니다. 이미 배포된 환경에서는 `deploy`를 다시 실행하지 않고 `status`로 확인하세요.

```sh
node --env-file=var/saigon.env --import tsx scripts/status.ts
```

외부 환경은 위의 `npm run dev`로 실행합니다. 예제 게임 서버(`src/game-main.ts`)는 더 이상 함께 실행하지 않습니다. smoke와 복구 잠금 도구는 예제 게임을 사용하므로 샘플을 운영 중지한 환경에서는 새 검증용 배포에서 실행하세요.

외부 로그인 비밀번호는 `var/bootstrap-accounts.json`, 배포 정보는 `var/deployment.json`, smoke 결과는 `var/smoke-<deploymentId>/report.json`에 기록됩니다. API는 이용자 개인키를 받지 않으며 smoke의 이용자 키는 별도의 테스트 클라이언트 파일입니다. 키·자격증명·DB·원본 서명 거래는 Git에서 제외합니다.

Smoke 클라이언트의 게임 DB는 `var/smoke-<deploymentId>/a.sqlite`, `b.sqlite`에 따로 있습니다. 위 화면용 게임 DB와 진행 기록을 공유하려면 `GAME_DATABASE_PATH`를 이 경로로 지정하세요. 복구 잠금 도구도 복구할 게임 서버와 같은 `GAME_DATABASE_PATH`로 실행해야 합니다.

## 지급 중단 복구

정상적인 중단은 게임 서버를 재시작하면 미완료 결제를 조회해 재개합니다. 아이템 지급과 지급 기록은 게임 DB의 같은 거래에서 저장됩니다.

지급 시작 이후 예외 환불은 다음 순서를 지킵니다.

1. 결제의 미지급을 확인할 근거를 준비합니다.
2. 아래 도구로 게임 DB의 지급 금지 잠금을 영속적으로 설정합니다. 이미 지급된 주문은 거절합니다.
3. 운영자와 네트워크 관리자가 화면에서 같은 결제 ID·증거 해시·유효기간에 각각 서명합니다.
4. 두 승인이 모이면 원래 지불자에게 환불됩니다.

```sh
npx tsx scripts/recovery-lock.ts game-b PAYMENT_ID 0xEVIDENCE_HASH
```

지급 여부가 불명확하면 환불하지 않습니다. 계약은 게임 DB의 잠금이나 실제 아이템 지급을 직접 판정할 수 없으므로 이 경로는 두 운영 주체의 확인을 신뢰합니다.

한 DB에는 하나의 작업 처리기만 실행합니다. API와 smoke는 프로세스 잠금으로 동시 실행을 차단합니다. 체인 노드는 서버와 별개이므로 DB만 보존하고 체인 상태를 삭제하면 동일 환경으로 복구할 수 없습니다.

### 운영자의 게임 서버 연결 정보

게임 운영자 계정의 **게임 서버 연결** 메뉴에서 승인된 게임별 API 주소·게임 ID·게임 API 키 발급을 한곳에서 제공합니다. 발급 직후 **환경 변수 설정 복사**, **실행 명령 복사**로 실제 키를 포함한 게임 서버 설정을 가져갈 수 있습니다. API 키는 발급 시 한 번만 표시되며 새로고침·로그아웃 뒤에는 다시 보이지 않습니다. 기존 키는 이름·범위·발급 기록을 확인하거나 폐기할 수 있습니다. `.env`를 자동으로 읽지 않는 게임은 게임 프로젝트 폴더에서 복사한 실행 명령을 사용하세요. 다른 컴퓨터의 게임 서버에는 접근 가능한 Metanomic 주소를 설정해야 합니다.
