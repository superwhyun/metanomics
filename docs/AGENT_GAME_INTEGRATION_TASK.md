# 다른 에이전트에 전달할 게임 연동 작업

아래 입력값을 채운 뒤 작업 지시문 전체를 구현할 에이전트에 전달한다. 실제 게임 경로·기능 범위·접근 가능한 API 주소는 전달할 때 지정해야 한다. 자격증명과 개인키는 문서에 적지 않고 실행 환경의 비밀 설정으로 제공한다.

## 입력값

| 항목                | 값                                                                |
| ------------------- | ----------------------------------------------------------------- |
| Metanomic 저장소    | `/Users/whyun/workspace/Metanomic` 또는 접근 가능한 체크아웃 경로 |
| 대상 게임 저장소    | `<절대 경로 또는 저장소 URL>`                                     |
| 승인된 gameId       | `<게임 ID, 미등록이면 등록 절차부터 수행>`                        |
| API 기본 주소       | `http://localhost:3300/v1` 또는 접근 가능한 환경 주소             |
| 자산                | `common-game-credit`                                              |
| 기능 범위           | `<계정 연결+보상 / 계정 연결+보상+결제>`                          |
| 보상 조건           | `<예: 주간 순위별 지급, 대상과 금액은 서버가 결정>`               |
| 판매 상품           | `<예: starter-pass, 4.000000 CGC, 수량 1>`                        |
| 공통 화면 변경 범위 | `<외부 게임용 공통 연결·승인 화면 추가를 포함하는지 명시>`        |

## 전달할 작업 지시문

대상 게임에 Metanomic 연동을 실제 구현해라. 위 입력값을 사용하고 먼저 Metanomic의 `docs/GAME_INTEGRATION.md`, `docs/openapi.json`, `docs/DESIGN.md`를 읽어라. 실제 구현은 `src/api.ts`, 서버 예제는 `src/game.ts`, 지갑·결제 서명 화면은 `web/app.ts`에서 확인해라. 문서와 동작이 다르면 차이를 확인하고 수정 범위에 맞게 바로잡아라.

1. 대상 게임의 로그인, 서버 보상 판정, 상품 주문, 인벤토리, DB 거래, 백그라운드 작업 구조를 확인하고 기존 구조에 연동해라. 사용자 작업을 보존하고 기존 게임을 별도 예제로 대체하지 마라.
2. 서버 비밀 설정에 API 주소·gameId·자산·게임 자격증명을 추가해라. 운영자 세션과 게임 자격증명, 이용자 세션을 구분하고 API 키를 클라이언트에 노출하지 마라. 게임 미등록·예산 부족이면 필요한 등록·예산 상태를 구체적으로 확인해라.
3. 자체 게임 세션으로 인증한 계정과 공통 이용자를 일회용 코드 교환으로 연결하고 DB에 저장해라. 브라우저가 제출한 임의의 playerId를 신뢰하지 마라.
4. 보상 조건·금액을 서버에서 결정해라. 요청 전에 rewardRef와 고정 요청 내용을 저장하고 중복 요청·응답 유실·재시작을 같은 업무로 복구해라. 작업 FINALIZED 후 지급 완료로 표시해라.
5. 결제 범위라면 주문·가격·상품을 서버에서 확정·저장하고 payments API를 호출해라. 이용자에게 결제 내용과 ERC-2612 사용 승인을 서명받고 이용자 세션으로 authorizations API에 제출해라. permit은 이용자 인증 GET payment에서 조회해라.
6. PAID에서는 delivery-claims를 요청하고 DELIVERY_CLAIMED 확정 후에만 아이템을 지급해라. paymentId 유일 제약 아래 인벤토리 변경과 지급 기록을 같은 DB 거래로 저장해라. 커밋 후 deliveryRef를 포함한 fulfillments를 재시도 가능하게 통지하고 COMPLETED까지 추적해라.
7. 이벤트 커서를 영속 저장하고 미완료 결제를 전체 순회하는 복구 작업을 구현해라. 지급 시작 이후 자동 환불하지 마라. 예외 복구가 필요하면 기존 지급 금지 잠금·공동 승인 절차를 따라라.
8. 이용자 UI에 연결 상태, 보상 진행 상태, 주문·금액 확인, 서명 취소·만료·처리 중·아이템 지급 결과를 표시해라. 현재 범용 로그인 리다이렉트·호스팅 결제창·외부 게임용 SDK·CORS가 제공된다고 가정하지 마라. 입력값의 공통 화면 변경 범위에 따라 Metanomic origin의 연결·승인 흐름을 구현해라. 일반 게임 연동이 예제 A/B 전용 프록시에 의존하지 않게 해라. 공통 화면 변경이 범위에서 빠졌다면 남는 사용자 흐름과 필요한 추가 작업을 명확히 보고하고 전체 연동 완료로 부르지 마라.
9. 문서의 완료 기준을 실제 API·계약·게임 DB로 검증해라. 같은 보상 재요청, 서명 없는 결제, 가격 변조, 지급·환불 경쟁, 아이템 지급 직후 재시작을 포함해라. 로컬에서는 100→10→4→1 순환과 이용자 7·게임 A 90·게임 B 3·아이템 1을 검증할 수 있다. 이는 초기 잔액 0, A 배분 100인 두 게임 시나리오의 기대값이다. 대상 게임 단독 연동은 해당 게임의 시작 예산과 잔액 변화를 따로 산정해라.
10. 구현 후 대상 게임의 실행·설정·검증 방법을 문서화하고 다음을 보고해라: 변경 경로, 실행 명령, 통과한 검사, 실제 브라우저·통합 검증 결과, 구현되지 않은 범위, Git 커밋·push 여부. 사용자 요청 없이 배포·공개·push하지 마라. 로컬 성공을 외부 테스트넷 성공으로 보고하지 마라.

완료는 API 호출 코드가 존재하는 상태가 아니라 실제 이용자가 계정을 연결하고 보상을 받거나, 승인한 결제로 아이템을 정확히 한 번 받는 상태다. 아직 없는 공통 승인 UI를 이미 있다고 가정한 구현이나 모의 API만 통과한 결과는 전체 연동 완료가 아니다.
